# レビュー観点チェックリスト

このドキュメントは、本テンプレートにおけるコードレビューの **単一の正本** です。
Copilot 向け指示（`.github/copilot-instructions.md`、`.github/instructions/**`）と
`CLAUDE.md` のレビュー観点は、ここから導出されます。観点を追加・変更する場合は
まずこのファイルを更新し、そのあとで導出物に反映してください（REV-08）。

`docs/requirements.md` §10 が原案です。

---

## 1. セキュリティ / Tauri 固有

- [ ] `src-tauri/capabilities/**` に権限を追加していないか。追加している場合、その window・その機能に本当に必要な範囲か（最小権限）
- [ ] フロントから受け取った値を、検証せずファイルパスやシェル引数に渡していないか
- [ ] 機密情報（トークン・鍵・パスワード）がフロントに返っていないか、ログに出ていないか
- [ ] CSP を緩めていないか。`tauri.conf.json` の `app.withGlobalTauri` を有効化していないか
  （既定の CSP は `style-src 'self' 'unsafe-inline'` — Tailwind/shadcn ui コンポーネントが
  生成するインラインスタイルのために必要な最小限の許可であり、`script-src` には
  `unsafe-inline`/`unsafe-eval` を含めていない。これ以上緩めていないか確認する）
- [ ] 外部から受け取った URL・パスの検証があるか（ディープリンク・ファイルパス）

## 2. Rust

- [ ] コマンド経路に `unwrap()` / `expect()` / `panic!` が無いか（プロセスごと落ちる）
- [ ] エラーが握り潰されていないか。共通エラー型（`AppError`）に変換されてフロントに伝わるか
- [ ] ロックを保持したまま `await` していないか
- [ ] ブロッキング I/O を非同期コンテキストで直接呼んでいないか（`spawn_blocking` を使うか）
- [ ] SQL が文字列連結で組まれていないか。`sqlx` のコンパイル時検証を通っているか
- [ ] マイグレーションが既存データを壊さないか（追加のみか、破壊的か）
- [ ] ロジックがコマンド関数に直接書かれていないか（テスト不能になる。`crates/core` に置くこと）

## 3. プラットフォーム分岐

- [ ] デスクトップ専用 API が共通コード（`crates/core`、モバイルもビルドするモジュール）に混入していないか
- [ ] `#[cfg(desktop)]` / `#[cfg(mobile)]` の対になる実装が揃っているか
- [ ] 追加した機能がモバイルで意味を持つか。持たない場合、UI 側でも出し分けているか（`src/lib/platform.ts`）

## 4. フロントエンド

- [ ] 生成物（`src/lib/bindings.ts`）を手編集していないか
- [ ] Rust 呼び出しのエラーがハンドリングされ、ユーザーに伝わるか（トースト等）
- [ ] ローディング状態が表現されているか（ネイティブ処理は数秒かかりうる）
- [ ] デスクトップ幅・モバイル幅の双方で崩れないか。セーフエリアを考慮しているか
- [ ] テーマトークンを使っているか（色を直接書いていないか）
- [ ] ハードコードされた文言が i18n の対象になっているか

## 5. テスト

- [ ] 変更された振る舞いに対応するテストがあるか
- [ ] テストが実装の内部構造ではなく振る舞いを検証しているか
- [ ] テスト名から「何が保証されているか」が読めるか
- [ ] テスト間に実行順依存や共有状態が無いか
- [ ] 失敗ケース・境界値が含まれているか

## 6. その他

- [ ] 依存を追加した理由が妥当か。バンドルサイズとライセンスを確認したか
- [ ] 設定値がハードコードされていないか（環境変数 / 設定ファイルに寄せているか）
- [ ] ドキュメント（README / architecture）の更新が必要な変更ではないか

---

## Copilot に任せないもの

- 自動生成ファイル（`bindings.ts`、lockfile、`src/components/ui/` のコピー物）は除外設定を入れ、レビュー対象から外す（REV-05）
- アーキテクチャの妥当性や機能の要否といった判断は、人間のレビューに残す
- Copilot のレビューは人間のレビューを代替しない。**観点の取りこぼしを減らす一次フィルタ** と位置づける（R-8）

## 更新フロー（REV-08）

不具合や見落としが発生した場合、次の順序で反映する。

1. 該当する不具合のパターンをこのファイルに観点として追記する
2. `.github/copilot-instructions.md` および `.github/instructions/**` に反映する
3. `CLAUDE.md` に反映する
4. 変更を伴う PR に、追記した観点を明記する
